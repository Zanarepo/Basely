Term	Meaning	Simple example
WIP	Work In Progress — work that has started but isn't finished	5 tickets currently being developed
WIP Limit	Maximum amount of work allowed in a workflow stage	Dev column can have max 3 items
Lead Time	Time from when work is requested to when it is delivered	Feature requested Monday → delivered Friday = 5 days
Cycle Time	Time from when work actually starts to when it finishes	Developer starts Tuesday → Done Thursday = 3 days
Throughput	Amount of work completed in a given period	20 tickets completed this week
Flow	How smoothly work moves through the system	Tickets continuously moving toward Done
Flow Efficiency	How much of the total time is actually spent working vs. waiting	4 hrs working / 10 hrs total = 40%
Bottleneck	A stage that slows down the entire workflow	QA has 15 items waiting
Pull System	Team pulls new work only when capacity becomes available	Dev finishes one → pulls next
Work Item	Individual piece of work moving through the board	Bug, feature, task, etc.
Explicit Policies	Clearly defined rules for how work moves	"Nothing enters QA without passing code review"
Classes of Service	Different handling rules/priorities for different work	Expedite, Standard, Fixed Date, Intangible
Service Level Expectation (SLE)	Expected timeframe for completing a work item	"85% of standard items completed within 5 days"
